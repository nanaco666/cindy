获取飞书会议内容(AI 总结 / 待办 / 章节 / 纪要正文)。想"总结我某天的会、看某场会讲了啥、拿会议纪要"时用这个——**这是获取飞书会议内容的唯一入口**。

## 核心:以日期为准,当天每场会都不漏

工具以 `date` 为核心,用 `calendarEvent.instanceView` 把当天日历**展开成真实会议实例**(每周例会等重复日程会被展开成"当天那一次",日期准确——这正是普通"列日历"接口会漏掉的)。当天每一场会都会被逐一枚举、标注内容获取状态,**绝不静默漏会**。

- **不传 `meeting_name`** → 返回当天**所有**会的清单 + 每场的获取状态(谁拿到了、谁没拿到、为什么)。
- **传 `meeting_name`** → 只看当天标题匹配的那(几)场;命中唯一一场时,直接返回该场完整纪要(正文 + 评论 + 图片清单,等于过去"按会议名取单场")。

## 为什么内容有时拿不到(飞书硬限制)

一场会的内容在飞书有两种形态、可见性不同:**智能纪要 docx**(自动生成、发给全体参会人,人人可读)和**妙记对象**(只在你自己的妙记列表里可见,飞书无"按会议反查妙记"的接口)。所以:**你不是组织者、且这场会没生成发全员的智能纪要 docx 时,内容你就是拿不到**。这时工具不会假装没这场会,而是把它列出来并写明原因(见下 `missing_*`)。

## 参数

- `date`(**必填**):`YYYY-MM-DD`(也接受 `2026/6/18`、`2026年6月18日`)。取这一天的会。
- `meeting_name`(可选):会议标题关键词(如「小镇周会」),与标题双向子串匹配。不传=当天全部;传=只看匹配的。
- `time_zone`(可选):默认 `Asia/Shanghai`。
- `calendar_id`(可选):默认 `primary`(本人主日历)。
- `include_content`(可选):是否读出正文。**默认**:传了 `meeting_name` 就读(给全文)、不传只给清单+链接(省 token)。设 `false` 强制只清单,`true` 强制读。

## 返回

命中唯一一场且需要正文时:直接返回该场完整纪要(同 `read_by_url`,含图)。

否则返回当天清单:`{ date, time_zone, calendar_id, events[], summary_line }`,其中每个 `event` 有:

- `summary` / `start_time` / `end_time` / `organizer` / `is_self_organizer`
- `source`:`"notes_doc"`(智能纪要 docx,最全)/ `"minutes"`(你的妙记)/ `"none"`
- `status`:
  - `got_notes_doc` / `got_minutes`:**拿到了**,带 `doc_url`/`doc_token` 或 `minute_url`/`minute_token`。
  - `missing_not_organizer`:你不是组织者,妙记归组织者、飞书限制拿不到 → `reason` 写明组织者 + 补救(让组织者开"自动纪要发全员",或把 docx 链接发你)。
  - `missing_no_record`:你可管理但没找到纪要 → 这场大概率没开妙记/未生成纪要。
- `summary_line`:一句话覆盖率概览(共几场、几场拿到、几场为什么没拿到)。

`status` 为 `missing_*` 的会**也在 `events` 里**——这是工具的核心契约:枚举不漏、拿不到也透明,不静默丢。

## 推荐工作流(总结"我某天的会")

```
直接 meeting_content(date=那天)   →  当天每场会 + 状态,一步到位、不漏
对想看正文的某场:meeting_content(date=那天, meeting_name=那场)  →  给全文
```

不需要再先调 `calendar_list_events` 自己列会——本工具已用 instanceView 在内部把当天会展开好了。

## 实现说明

instanceView 展开当天实例 → 过滤掉全天事件(请假等)/已取消/无标题 → (可选 name 过滤)→ 逐场(并发)定位:智能纪要 docx 优先(会议名+完整中文日期搜 + 代码侧"会议名匹配 + 日期完全一致"严格筛),没命中再用该会精确时间窗搜本人妙记。组织者预判用日历自带的 `attendee_ability`(启发式),不额外调接口。以当前登录用户的飞书权限操作。
