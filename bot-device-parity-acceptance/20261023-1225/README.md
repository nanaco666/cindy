环境说明（与产品无关，仅供复现）：
- `pnpm install` 的 postinstall 与 dev 启动前置步骤用 msys 的 GNU `tar` 解压 pi 的 zip 失败（`tar: Cannot connect to C: resolve failed`），启动 verdict 为 `STARTUP_FAILED`。绕过方式：启动命令前把 Windows 自带 bsdtar（`C:\Windows\System32\tar.exe`）复制到一个目录并置于 PATH 最前，**未改仓库代码**。
- 启动器对 A、B 的首次启动及 B 的重启都返回 `DESKTOP_DEV_VERDICT=failed code=STARTUP_TIMEOUT`（“120s 内未完成窗口/登录/数据库启动”），原因是首次 vite 编译慢；实例随后实际正常起来（CDP 可连，登录成功）。按规则，verdict 不是 `ready` 本不应声称启动成功，这里以 CDP 可连与登录成功为实际依据，特此注明。
- 登录：登录页勾选条款 → SSO → 输入 `xd` → 继续；A 首次需在系统浏览器完成验证（约 5 分钟后通过），B 随后很快通过。

### S1-c 断线与恢复

- 步骤：只结束 B 的主进程树（`taskkill /T /F /PID <B 主进程>`，12:46:43）；观察 A；再用 `pnpm restart:desktop:remote --region=cn --isolated=accept-b` 重启 B；观察 A 是否自动恢复。
- 期望：A 的远程设置页显示离线/断线状态且布局不跳动；B 重启后自动恢复。
- 实际：
  - A 日志：`device-link request failed ... code=DEVICE_OFFLINE`；`[ERROR] [console] Error occurred in handler for 'device-link:topic-unsubscribe': Error: [DEVICE_LINK_NOT_CONNECTED] relay rejected reliable link (DEVICE_OFFLINE)`。
  - A 界面：伙伴视图整体退为云端只读对话，顶部横幅“主力电脑「验收 B · 伙伴主力」没有开放远程控制 / 在这台电脑继续…”，底部“这里是云端保存的对话，只能查看”。点右上“设置”图标，URL 追加 `?settings=1` 但**没有任何设置面板**，也没有离线提示。
  - 横幅原因文案与事实不符：B 的“允许同账号设备控制本机”是开着的，只是进程不在。见 D1。
  - B 重启后 A 在 12:53:08（B CDP 恢复后约 1.5 分钟）自动回到实时视图，无需手动操作；设置面板可再次正常打开。
- 结论：**自动恢复 通过；离线展示 不符合期望（D1）**。
- 证据：`S1-disconnect-recover/`（5 张截图 + `时间线.txt`）。
