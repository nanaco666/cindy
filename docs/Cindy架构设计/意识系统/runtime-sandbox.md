# 意识运行时与沙箱(Runtime & Sandbox)

> 状态:**v1.1(2026-07-09)已评审定案,待动工 C3a**。基于 C2 收官后与 Lizi 的两轮对齐(五问 + 追问),运行时架构与原待评审项均已拍板(定案记录见 §11)。布局与面板停靠机制不在本篇(见 layout-tree.md),声明型意识(v1)已交付、不受本篇影响。

## 0. 已拍板的前提(2026-07-09 五问对齐结论)

1. **界面由意识自己的沙箱代码来画**,主机不代画。官方提供一套 **UI 组件库**(按钮/列表/卡片/开关等,自带主题 token),用官方组件搭的面板天然与主界面同风格;不用官方组件、完全自绘也允许。
2. **每段意识一个独立沙箱进程(单间 + 焊死门窗)**,不采用共用进程分房间的方案——崩溃隔离必须是进程级的物理隔离,不是代码软墙。
3. **五个卡槽是意识能力的全部出口**(§5),声明用哪几个、运行时就只能用哪几个,代码层强制。
4. **权限弹窗 = App 式人话清单**(§6),由主机按声明的卡槽自动生成,意识无法美化或隐瞒。
5. **两条安全铁律**照写(§7):模型调用只走主机统一通道;意识自有凭证锁进专属保险库。
6. **核心愿景:做意识的工具就是 Maker 自己**(§9)——用户对 agent 说需求,agent 用官方模板 + 组件库生成 `.cindy`,注入即测,用户不需要学任何开发规则。

## 0.5 形态收敛与隐喻对照(2026-07-12 Lizi 定案:意识只有一种形态)

**意识只有一种产品形态:电子脑(Cyberbrain/電脳/전뇌,机器字段 `kind: 'chip'`)**——带可执行代码、跑独立沙箱进程、经五卡槽与 Cindy 交互并自绘界面。判据(Lizi 原话归纳):意识的本质是"**能和 Cindy 交互 + 有独特的渲染能力**",达不到这两条的资产不构成一种意识形态。

**沿革**:2026-07-09 曾定案三形态"经验/躯壳/电子脑"(攻壳语系词,叙事为"意识的觉醒程度":经验=未成形、躯壳=未觉醒、电子脑=觉醒),2026-07-12 复盘收敛为单形态,处置如下:

- **"经验"档(Experience,提示词层,原规划未来收编 Skill)——取消不做**:纯 prompt 资产与 Skill 体系完全重叠,该场景由 Skill 覆盖;真有"给普通用户分发提示词包"的需求,由 agent 替用户装 Skill 即可(§0 愿景 6),撑不起一个独立形态。
- **"躯壳"档(Shell/義体/의체,declaration 静态档)——彻底移除,不留兼容层**(Lizi 确认无存量包,对齐 07-08"无曾用名兼容"先例):它的真实价值是 C1/C2 期沙箱建成前的工程脚手架(用无代码意识先跑通装入/布局/生命周期基建),该使命已完成;作为产品形态不成立(静态面板不如开个网页)。校验只认 `schemaVersion: 2` + `kind: 'chip'`,panel 一律 html 自绘(静态 body 面板随之删除),装入/打包两侧同一口径。
- 机器字段 `kind` 于 2026-07-12 晚间进一步定案为**可省略**(单形态后纯冗余):校验缺省归一化为 `'chip'`,写了非 chip 值仍拒;新意识不必再写。

**UI 纪律:形态词不上界面**(单形态后天然无形态词可上)。用户层一律如实描述"这段意识**包含什么**"(面板/可执行代码/模型调用/注册工具/订阅消息/消息卡片,`ghostContentKeys`),设置页信息卡与注入确认弹窗均按内容清单展示。注意:中文语境「电子脑」永远写全三字(避免与"电脑=计算机"撞词);「记忆」一词保留给 agent 记忆系统专用。

**完整隐喻对照**(向新人讲架构用):壳=Cindy 主机;脑=主机的 brain 容器(意识们的住处);意识=一枚 .cindy;电子脑=意识自带的沙箱进程(它自己的思考器官);脑机接口=管子(卡槽网关,电子脑与主机世界唯一的连接线);防壁=权限清单 + slots 白名单 + 焊死门窗。

## 1. 目标与非目标

**目标**:让 `.cindy` 从"声明卡(纯数据)"升级为"芯片卡(带代码)"——意识可以自绘面板界面、订阅事件、注册工具、渲染消息卡片、申请模型调用;同时保证:**安全**(不越权、不偷数据、不偷钥匙)与**稳定**(意识可以自己崩,绝不带崩主进程或其它意识)。

**非目标(本篇不做)**:意识商店 / 在线分发(维持本地 `.cindy` 文件导入);意识间互相通信;意识后台常驻**任务**(定时任务等,后续里程碑;注意与 §4 的 `launch: "resident"` 常驻**进程**区分——后者已于 2026-07-12 落地,只是进程在场,不含任何定时/后台任务机制);对声明型意识做任何改动。

## 2. 一段芯片型意识由什么组成

`.cindy` 仍是 zip,`ghost.json` 升级(2026-07-12 起校验只认本形态,v1 声明型清单已移除):

```jsonc
{
  "schemaVersion": 2,
  "id": "stock-watch",
  "name": "股价盯盘",
  "version": "1.0.0",
  "kind": "chip",                    // 恒为 "chip"(2026-07-12 单形态定案)
  "entry": "main.js",               // 逻辑入口(跑在沙箱里)
  "panel": {
    "title": "股价盯盘",
    "html": "panel.html",           // 面板界面入口(意识自己画)
    "minWidth": 280,
    "defaultFraction": 0.2
  },
  "settingsHtml": "settings.html",  // 可选:设置页「自定义设置区」插槽的界面
  "slots": ["panel", "model"]        // 声明用哪些卡槽 → 权限清单据此生成
}
```

要点:

- **slots 是白名单**:没写的槽,运行时对应接口直接不存在(§6),不是"调了报错"而是"根本没有"。
- 注入必弹权限清单(单形态后无免弹窗形态)。
- `settingsHtml` 填充 C2c-2 预留的「意识自定义设置区」插槽(**渲染通道已开通,2026-07-13**:
  设置页详情里与面板同款沙箱 webview 真实渲染,attach 闸白名单 = panel.html + settingsHtml;
  高度缺省随内容自适应(宿主 executeJavaScript 量 guest body 内容高,不受信数值 clamp 48–800,
  量到前占位 160——矮内容真收下去,不垫 160 的底),
  声明可选 `settingsHeight` = 固定高度;注入基线背景 = 设置卡片色,与相邻卡片无缝);
  不提供则整块不出现。
- 意识自定义参数走协议保留路径 **`/kv`**(与 `/wake` `/gallery` `/media/` `/__boot__` 并列):
  GET 读 / PUT·POST 整体覆盖写,值须 JSON object ≤64KB,主机落 `userData/ghost-kv/<id>.json`
  (单意识单文件,分区断网闸保证跨意识摸不到)。**卸下清除、沉睡保留**。凭证明文仍走
  C4 保险库,/kv 不承载任何密钥。
- 凭证收单一律在意识 settingsHtml(2026-07-13 宿主凭证渲染整体退役,声明 user 凭证
  必须声明 settingsHtml;`input` 字段退役:遗留 `"ghost"` 接受并忽略、`"host"` 拒):
  意识设置页自己收单、经保留路径 **`/secrets/<key>`** PUT 一次性入库
  (只写通道:GET `/secrets` 只回 `{key, saved, tail?}` 状态,值永远读不回——tail 是
  入库瞬间截存的尾 4 位指纹,值不足 12 字符不产;DELETE 清除)。login-email 派生凭证
  无输入动作、不可配置(PUT/DELETE 405),GET 回 `{key, saved, identity}`——identity =
  当前登录邮箱,供意识 settingsHtml 只读展示"用的是哪个身份"(确认框已披露"将使用
  你的登录邮箱",且注入时它自己的服务端本就可见,不算新增泄露面;xd-pages 即此模式)。
  保管(safeStorage)与注入(主机代发)不变,详见 capability-permissions.md C4。

## 3. 沙箱形态:单间 + 焊死门窗

**"独立进程"解决住哪(崩了不连累别人),"沙箱"解决能碰什么(焊死门窗)——两样都要。**

### 技术选型(2026-07-09 定案:方案 A)

| | 方案 A:每意识一个隐藏沙箱网页进程(推荐) | 方案 B:每意识一个 utilityProcess |
|---|---|---|
| 隔离强度 | **Chromium 渲染沙箱,操作系统级**,浏览器同款——无文件系统、无任意网络宿主权限、无系统调用 | 进程隔离有,但 Node 环境天然全能力,"焊死门窗"要自己造(权限模型自研,风险高) |
| 界面怎么画 | 天然满足——意识面板本来就是一块网页,逻辑与界面同住一间 | 界面还得另开一块沙箱网页,一段意识两个进程,复杂 |
| 崩溃隔离 | 进程级,崩了主机收 render-process-gone 信号收尸 | 进程级,同样成立 |
| 内存开销 | 一间约几十 MB,靠"用到才开、闲了就关"(§4)控制 | 略轻,但两进程方案抵消优势 |
| 结论 | **逻辑 + 界面同住一个真沙箱,实现最直、边界最硬** | 不选:等于自己重新发明浏览器沙箱 |

方案 A 落地形态:每段唤醒且干活中的意识 = 一个 **sandbox 开启、Node 关闭、独立 session 分区**的隐藏网页环境;面板可见时这块网页就地作为面板内容渲染(嵌进布局树的 pane 里),面板不可见但有活要干时离屏运行。它与主机之间**只有一根管子**(受控的消息桥),五个卡槽的所有往来全走这根管子,桥上每条消息按 slots 白名单过滤。

### 成熟方案对照(2026-07-09 评审补充)

| 前辈 | 模式 | 结论 |
|---|---|---|
| Chrome 扩展 | 每扩展独立进程 + 安装时权限清单 | **与本方案同构**——全球验证最充分的插件沙箱;方案 A 即"在 Electron 里复刻 Chrome 扩展模型" |
| VSCode 插件 | 全部插件共居一个 extension host 进程,且持完整 Node 权限(可读全盘) | **反例**:一个插件卡死全体陪葬("扩展宿主已停止响应"即此),安全模型公认偏弱;其自定义 UI 反而用的正是 sandboxed webview 路线 |
| WoW 插件 | 与游戏同进程的 Lua 软沙箱,靠收窄 API 面保安全 | **反例**:无物理隔离,坏插件直接拖累游戏;但"API 面即权限面"的思路与五卡槽同源 |
| Figma 插件 | 界面在沙箱 iframe,逻辑套软件模拟的 JS 虚拟机 | 与 Chrome 精神同源但**隔离弱一级**:Figma 虽有桌面客户端,但那只是同一网页的壳,插件系统必须同时跑在浏览器标签页里,只能按最弱环境(无权开进程)设计——"同屋套笼子",插件逻辑与编辑器挤同一主线程,死循环插件能卡死整个 Figma。XDMaker 只有桌面形态、无浏览器版包袱,进程能力实打实可用,故走 Chrome 路线;Figma 的价值在佐证"插件界面 = 沙箱网页"是主流 |

### 跨端前瞻:手机版 = 远程视网膜(2026-07-09 评审两轮修订)

手机版(apps/mobile)是**纯控制端**——不跑 agent、不落业务数据,一切状态活在被控桌面上,经 device-link 远控协议镜像与操作(受 `REMOTE_INVOKE_ALLOWLIST` 白名单约束)。意识系统顺延同一世界观:**意识永远住在桌面的脑(brain)里,手机只是一块远程视网膜**:

- **主机侧零改动**:意识进程、保险库、模型通道、卡槽网关、生命周期全在桌面,与"会话活在桌面"同构;
- **手机显示面板**:手机本地用系统沙箱网页容器(iOS WKWebView 强制独立进程 / Android 8+ 沙箱渲染进程)装载意识界面文件(经远控通道取),其管子**顺远控隧道接回桌面网关**——意识代码零修改、无感知,slots 白名单照常在桌面侧强制;远控白名单在 `packages/device-link` 侧受控扩展,手机端单方面改不动边界;
- **卡槽③(消息卡片)在手机近乎免费**:聊天流本来就镜像,卡片随之;
- **桌面不在线 = 意识不在场**,与手机版既有语义("无桌面即无会话")一致。

选"沙箱网页"的隐藏红利正在于此:网页是唯一在手机上也有原生沙箱容器的运行时。近期不排期,但**任何实现不得引入"只有桌面能跑"的假设**(如在意识侧暴露 Electron 特有接口)。

### 焊死门窗的清单

- 无 Node 能力、无主机文件系统访问;能读的只有自己安装目录里的静态文件(自己的 html/js/图片)。
- **网络永远不直连**(沙箱本体零网络,2026-07-09 定案、无待议空间)。需要外部数据的意识走管子申请**主机代发**:manifest 声明域名白名单 → 权限清单如实展示("将访问 jira.xd.com")→ 主机端对照白名单放行、代发、递回结果。放行 / 审计 / 限流全在主机,意识不存在把数据发往未声明地址的旁路。**内部工具类意识(查 Jira / 飞书 / GitLab 等)由此完全可行**,这是"把现有内部工具逐步意识化"路线的网络前提。
- 主机 IPC、Electron 接口、其它意识,一概不可达;管子对面只有主机的卡槽网关(五卡槽 + 两项管子服务:保险库、代发网络)。

## 4. 生命周期与清理纪律

**第一条原则:进程是干活时才存在的东西,不是装了就常驻的东西。**

> **显式例外(2026-07-12 增补):`launch: "resident"` 启动模式。** 身份卡可声明
> `launch` 字段(缺省 `"on-demand"` = 本节原则原样生效;`"resident"` = 唤醒即
> 启动:enable 时拉起、应用启动时对"已唤醒"者拉起、更新换代后立即用新代码
> 重新拉起)。约束:作者声明 + 装入确认框如实标注"常驻运行"(用户知情才背
> 这个后台进程);沉睡 / 抽离 / 退出的熄灯规则**与模式无关、原样适用**;崩溃
> 后无自动重启(熔断保护照常,60s 3 崩转沉睡语义不变)。适用场景:订阅型
> 意识(要旁听消息流就得在场)、需秒响应的面板交互;绝大多数意识不该用。

| 状态 | 磁盘 | 界面 | 进程 |
|---|---|---|---|
| 已抽离 | 无 | 无(布局留记忆) | 无 |
| 沉睡(唤醒开关关) | 装着 | 面板隐藏、能力全下线 | **无,零开销** |
| 唤醒但闲着 | 装着 | 面板在场 | **仍然无** |
| 干活中 | 装着 | 在场 | 一个单间 |

- **拉起时机**:面板滚进视野要渲染 / 订阅的事件到达 / agent 调用它注册的工具 / 模型调用回包要送达——确实有活才开门。
- **熄灯时机**:沉睡、抽离 → 立刻关;闲置超时(面板不可见 + 无未决事件,**宽限 5 分钟**再熄灯,避免来回切换反复冷启动)→ 自动休眠;主机正常退出 → 逐个关完才走。"面板不可见"的判定 = 贴边折叠收起 / 设置页接管(只剩聊天区)/ 被其它面板最大化遮挡 / 窗口最小化,四种任一即算;未来新增浮层、标签页等形态时纳入同一判定,规则不变。
- **先礼后兵**:关闭先通知体面退出,限时未退强杀;Windows 无 POSIX 信号语义,显式 kill 兜底(规范 15)。
- **孤儿进程双保险**(主机被强杀、来不及收尾的场景):
  1. **孩子盯父亲**:管子断了 = 主机没了,意识进程自行退出(不依赖主机来杀);
  2. **开机扫尸体**:主机启动时按进程标记找出上一辈子残留的意识进程,补刀。
- **崩溃处理**:意识崩 = 它自己的单间死;主机收尸,面板位置显示"这段意识已崩溃(重启)",主界面与其它意识不受任何影响;**60 秒内崩 3 次自动熔断为沉睡态**(2026-07-09 定案),面板显示"反复崩溃,已休眠",防止崩溃循环空耗。

## 5. 五个卡槽(能力接口)

意识对主机的全部能力出口,走同一根管子,按 slots 白名单放行:

| 卡槽 | 方向 | 大白话 | 例子 |
|---|---|---|---|
| ① subscribe 订阅/拦截 | 主机 ↔ 意识 | 旁听会话事件(did-,fire-and-forget)+ 拦截用户消息(will-,主机停等裁决) | 用量统计意识记 token;合规意识拦截敏感消息 |
| ② tool 注册工具 | 意识 → agent | 给 agent 挂新工具(底层即 MCP) | 内部 wiki 意识给 agent 加"查 wiki"能力 |
| ③ card 消息卡片 | 意识 → 聊天流 | 在聊天里渲染自定义卡片 | 天气结果显示成图文卡 |
| ④ panel 面板 | 意识 → 布局树 | 常驻一块自绘界面(+ 设置页自定义区) | 画图意识的画廊面板 |
| ⑤ model 模型调用 | 意识 → 主机代办 | 要用 AI 只能打报告让主机代调 | 翻译意识送文字去翻译,费用走用户统一账户 |

**开闸进度**:④(C3b)、②⑤(C3d)、③(C3d' 海报模式,2026-07-12 落地,细节见 §5.5 b 路注)、
① subscribe(旁听 did- + 拦截 will-,2026-07-12 落地,细节见 §5.6)已全部通电。五槽齐开。

### 5.5 主循环:调用即渲染(2026-07-09 Lizi 定案)

意识系统的核心数据流——**交互入口永远是主聊天流,面板是被动画布**:

```
用户在聊天里对 Cindy 说话
  → agent 决定调用某意识注册的工具(卡槽②)
  → 管子把调用送进该意识的电子脑(离屏逻辑页,按需拉起)
  → 电子脑干活(要用 AI 走卡槽⑤主机代办;要外部数据走主机代发)
  → 三路输出:
      a. 工具结果回给 agent(对话继续)
      b. 聊天流里这次调用渲染成意识自定义的卡片(卡槽③)
      c. 渲染数据推给自己的面板(卡槽④;无面板的意识跳过此路)
```

**b 路实现口径(C3d' 海报模式,2026-07-12 落地)**:电子脑收到 tool-call 后经管子
上行 `card-update {callId, html, height}` 供片(0..N 版,过程即第一版、交卷前发终版;
主机限速 ≥1s/版 + 32KB 上限);主机 sanitizer 白名单重建(零脚本、图片仅本意识名下
cindy-media 地址)→ 落 `ghost_cards` 表(upsert by callId)→ 推 renderer;渲染宿主是
聊天流里的 `sandbox="allow-same-origin"`(**无 allow-scripts**)iframe + meta CSP,
卡上方主机画统一身份头(头像/名字/工具/状态,意识不可触)。srcDoc 头部还注一段
主机主题变量块(`:root{--token:value}`,白名单与面板 `ghostPanelTheme.ts` 同源,经
`useGhostCardThemeVars` 订阅换肤重建 srcDoc)——意识用 `var(--xxx)` 即可跟主题、
写死配色的意识不引用即无感知(纯加法能力,非强制)。配对令牌 = 主机仅在
"该单真供过卡"时注入 tool_result 顶层的 `xdt_card_id`(= callId);in-flight 进度卡
claude 走 MCP `_meta["claudecode/toolUseId"]` 精确锚,codex 走同 ghostId 启发式、
settle 自校正。未供卡 = 聊天渲染逐像素回退今日默认(通用媒体卡)。交互(按钮/
实时刷新)不在海报模式内——协议 `v` 字段为未来交互档预留。

四条铁则(Lizi 原话归纳):

1. 用户可自定义面板渲染任何内容(卡槽④,已实装);
2. 面板能收到主聊天流里"这段意识被调用"的结果并渲染(上图 c 路);
3. 聊天流里意识被调用时的卡片渲染可由意识自定义(卡槽③);
4. **主机不提供任何"从面板驱动 Cindy"的通道**(2026-07-09 修准:边界是
   **能力级**而非控件级)——面板内可以有自己的交互控件,那是意识作者的
   自留地,只与意识自身逻辑互动;但方向盘只有一个:Cindy 调用意识、意识
   回传渲染。主机的本分 = 提供投递 / 接收 / 订阅的消息接口(管子 + 卡槽),
   有没有输入框主机不管,有没有那条通道主机说了算(而它不存在)。

**触发方式(2026-07-09 Lizi 定案:对齐 Skill 的双触发模式)**——意识在
聊天流里有两条被调起的路,和 Skill 完全同构,共用 `/` 命令入口:

- **显式 command**:输入框敲 `/<command>`(命令面板可选),确定性触发——
  用户点名,agent 必须调它。**指令由意识作者在身份卡自定**(manifest
  `command` 字段,1–32 字符、无空白与斜杠、允许中文如 `/画图`,须有 tools
  可干活);**装入时主机与已装意识查重**(大小写折叠),撞名即拒
  (`command-conflict`),不静默改名——由用户抽离占用方或作者换名解决;
- **语言推理**:用户自然说话,agent 读意识工具的 description 自行判断调用
  (工具经卡槽②注册后天然获得,无需额外机制)。

实现要点:面板页与电子脑(逻辑页)**同源同分区**(同一间房里的两块屏),
面内互通走同源广播通道(BroadcastChannel)——不出沙箱边界、主机零中转;
面板隐藏时逻辑页照常接调用,面板回来时从同分区取回状态补渲染。
**管子(脑机接口)只接在电子脑上**:离屏逻辑页有桥,面板页零桥零特权——
面板被攻破也摸不到主机,这是"被动画布"的结构保证。

### 5.6 订阅槽①:旁听 + 拦截(2026-07-12 落地)

一种事件模型两个类型,按"能不能改流程"分:
- **监听 \`did-\`** = 纯数据通知(事后旁听,改变不了流程);
- **钩子 \`will-\`** = 主机在某点停下来交给意识做、做完继续(闸门 + 变换器)。

事件名前缀即类型;将来开新钩子点 = 加 \`will-\` 事件 + 同一裁决协议,无需推翻。

**协议**(\`shared/ghost.ts\`):下行 \`GhostPipeEventPush\`——\`did-\` 带 \`topic/seq/dropped\`
(\`did-turn-start\` / \`did-turn-end\` / \`did-session-created\` / \`did-session-archived\` /
\`did-session-switched\`(2026-07-13 增:用户把哪个会话切到台前;renderer MainLayout
路由 effect 经 'ghosts:session-focused' 单向上报,main 侧 createGhostSessionFocusTracker
去重——连续同 id 不发、切去非会话页只清位、切回算新切换,资格门与 created/archived
同口径),全元数据,turn-end 带 usage,各字段可选因 cc/codex 上报详尽度不同);\`will-user-message\`
带 \`hookId\` + \`{sessionId, text}\`。上行 \`GhostPipeEventVerdict {hookId, action:'allow'|'block'|'rewrite', reason?, text?}\`——
三种收尾:allow 原样继续 / block 打回(reason ≤200)/ rewrite 改写正文再继续(text ≤16000,
替换即将落库/显示/交给 agent 的正文)。常量:\`GHOST_SUB_QUEUE_MAX=100\`、
\`GHOST_HOOK_TIMEOUT_MS=3000\`、\`GHOST_HOOK_FUSE_THRESHOLD=3\`、\`GHOST_HOOK_REWRITE_MAX_CHARS=16000\`。

**网关**(\`cindy-brain/subscriptionGateway.ts\`,纯 DI 可单测):\`did-\` 按 topic 白名单
扇出,在跑直投 / 熄灯进队列(溢出丢最旧带 dropped)/ 事件到达按需拉起顺序补投;
\`will-\` 串行询问声明钩子的意识(装入序,**链式变换**:前一个 rewrite 输出是后一个输入,
任一 block 即短路),单意识硬超时 fail-open,连续失败熔断降级只旁听。
\`GhostTurnTranslator\` 把 AgentEvent(status/done/error)折叠成 did-turn-*(maker-core 无
独立 turn 事件,靠 status.isRunning 翻转 + done/terminal error)。

**接入点**:事件源 tap 叠加在 \`wireSessionToIpc\` 的 \`session.onEvent\`(只投用户主会话:
source=desktop/shared、orcaRole=null,行级谓词 isGhostEligibleSessionRow——shared
= 分享导入后用户自己在用的会话,2026-07-13 起放行;IM 渠道/自动化/orca 仍排除;
自动化轮次 turnOrigin≠user 滤除);拦截缝在
\`AgentInputCoordinator.drain\` 的落库/派发之前(agent 无关,cc/codex 通吃,不碰 maker-core
热路径),\`screenUserMessage\` 命中 block 即丢弃排队项 + 广播 \`ghosts:user-message-blocked\`;
命中 rewrite 则原地改 head 的 text/persistedContent/chatMessage.content(送 agent 与落库都用
改写版)+ 广播 \`ghosts:user-message-rewritten\`(带 originalText 供留痕)。上行 \`event-verdict\`
在 \`ghost-pipe:send\` 分支。会话生命周期从 localDb sessions handler fire-and-forget 通知。

**交互**(2026-07-13 定稿,Lizi:去掉主机自造的脚标/徽章,意识返回什么直接显示):
- **block** — 消息发不出去(不落库不起 turn),气泡照常显示,其下渲一条 **error 红条
  (ErrorMessageCard),内容 = 意识返回的 reason 原文**(主机直接显示,不加框不署名)。
  用户用消息的编辑铅笔改了重发——被拦消息未落库、无 turn 可 rewind,故 EditBox 走
  \`onCommitOverride\` 普通重发(\`resendBlockedMessage\`,**不 rewind、不 bypass 钩子**:
  改干净了自然通过,没改就再次被拦)。**无"强制发送"**,拦截即发不出去。
- **rewrite** — 气泡 content 静默换成改写版(与交给 agent 的一致),**无标记、无弹窗**;
  空改写 / 改写等于原文被忽略。allow/超时用户零感知,全程无 loading 帧。

**信任边界**:reason / text 文本由意识供(主机分别截断 200 / 16000 字符),但红条、气泡的
**整块 UI 主机画**(意识伪装不了、冒充不了别的意识)。设计取舍:主机不再替意识画"署名
脚标 / 优化徽章"——那些框架样式和文案不一定真符合意识语义,只在特定场景碰巧贴合;意识
要表达什么就自己写进 reason 文本里直接显示。

**拦截点语义边界(v1 刻意为之)**:钩子拦的是「即将启动新 turn 的用户消息」——
运行中 turn 里的用户插话(steer)**不经**钩子(拦下 = turn 压根不启动的语义决定;
插话并入 in-flight turn,没有"不启动"可言)。手册 §4.6 已向作者明示,别让意识作者
假设能看到会话里的每一句话;将来若有真实合规诉求再评估 steer 路径筛查。

#### 出口钩子 will-assistant-message(2026-07-13 落地)

出口钩子是 AI 回复的**通用后处理点**(不限定用途:纯副作用审计 / 任意正文变换 /
基于结果重绘呈现——形态与原文无关)。与入口钩子(闸在发送前)
不同,它是**"先定案 → 一拍后替换"(Design A)**:AI 回复照常流式 + 正常落库显示,裁决
在 turn 结束后的**独立异步续跑**里跑,回来再原地更新那条已落库的 assistant 消息。

- **协议**:下行 \`GhostPipeEventPush\` 增 \`will-assistant-message\` 分支(\`hookId\` +
  \`{sessionId, text=回复全文}\`);上行 \`GhostPipeEventVerdict.action\` 扩 \`'render'\`(带
  \`html\`/\`height\`)。动作集 **allow / rewrite / render**(**无 block**——AI 已生成拦无意义);
  超时常量单列 \`GHOST_ASSISTANT_HOOK_TIMEOUT_MS = 5min\`(后台后置钩,容许长处理:合规
  接口 / 自研 LLM 润色 / 出图),入口钩子仍 3s。
- **网关**:\`screenAssistantMessage\` 镜像 \`screenUserMessage\`(串行链式,rewrite 叠加),
  \`render\` **最后一个胜出**;\`askOne\` 按钩名取超时;\`handleVerdict\` 透传 html/height。
- **接入点(不碰 maker-core,规则 10)**:\`register.ts\` 的 \`session.onEvent\` done 边界
  (\`flushAssistantBlock\` 之后)。同步守卫 \`hasEnabledGhostAssistantHook()\`——无此类意识
  **不 schedule**,行为与今天逐字节一致(零回归)。有则 \`runGhostAssistantReplyHook\`
  (\`assistantReplyHook.ts\`,DI 可测)在独立续跑里裁决 + 落地:rewrite → \`updateMessageContent\`
  + 广播 \`ghosts:assistant-message-rewritten\`(气泡静默换文本);render → 净化(同 card 槽)
  + 持久化 \`ghost_cards\`(callId = **该 assistant 消息 clientId**)+ 推 \`ghosts:card-updated\`。
- **render 复用卡片管线**:卡以消息 clientId 当 callId 存,renderer \`ghostCardStore.byCallId\`
  命中该 clientId 即判定"气泡被自绘替换"——**卡的存在本身即标记**,无需另设消息字段;
  历史回放靠 \`listCardsBySession\`(\`ghosts:card:list-by-session\`)会话打开时批量灌 byCallId。
  \`AssistantMessage\` 渲 \`GhostToolCard\` + "查看原文"切换(原文仍在库,信任边界)。
- **处理中指示**:\`ghosts:assistant-message-pending\` 开/关,气泡挂"意识处理中"(纯瞬态)。
- **fail-open**:超时/崩溃/净化拒 → 保留 AI 原文定案,绝不丢回复。

## 6. 权限清单(App 式确认)

注入芯片型意识时,确认弹窗展示由 slots **自动生成**的人话清单,例:

> 这段意识将会:
> - 🖥 在界面上显示自己的面板
> - 👂 旁听你的会话消息(隐私,加重提示)
> - 🤖 使用 AI,费用计入你的账户(花钱,加重提示)

三条硬规矩:

1. 清单由主机生成,数据源只有 manifest 的 slots——意识没有任何自定义文案的口子;
2. **没声明的槽 = 接口不存在**,不是运行时拒绝,而是管子网关根本不挂那段处理;
3. 敏感项排最上并加重样式(用模型 = 花钱、订阅消息 = 隐私、网络 = 外联)。


## 7. 两条铁律落地

- **统一模型通道**:意识不许自带 AI 钥匙。卡槽 ⑤ 的报告进入主机的统一模型通道,计费、审计、模型路由、并发闸(默认不限,可按意识配上限;超限拒单不排队)全在主机;回包经管子送回。坏意识既偷不了用户额度,也没有旁路把数据发去不明服务器(网络默认全禁,§3)。
- **沙箱保险库**(2026-07-09 评审展开为三层设计):
  1. **存哪**:主机用户数据区,按意识 id 分隔间;**不放在意识安装目录里**(防随 .cindy 重打包外泄);落盘前经操作系统级凭据加密(Windows DPAPI / macOS 钥匙串派生密钥),磁盘上是密文。
  2. **怎么取**:唯一入口是意识自己那根管子上的保险库接口。**身份由主机在开进程时钉死**——管子生来打着意识 id,意识无法自报家门冒充别人,查库只能命中自己的隔间。
  3. **为什么跨意识绝对拿不到(结构保证,非约定)**:① 沙箱无文件系统能力,摸不到主机存储文件;② 意识之间不存在任何通信通道;③ 唯一的门(管子)身份固定。诚实边界:主机进程作为可信地基技术上持有解密能力(它须代存取),铁律的"宿主无读取接口"指不提供任何把凭证暴露给界面层、日志或其它意识的 API。
  抽离意识时隔间随之销毁,确认弹窗提示"将连同它保存的凭证一起删除"(2026-07-09 定案,不静默删)。

## 8. 官方组件库与视觉一致性

- 发一套 **Cindy UI 组件库**(随主机内置,面板环境里直接可用):按钮 / 列表 / 卡片 / 开关 / 输入框等,消费主机下发的主题 token(当前主题的颜色变量随管子同步进沙箱),**主题切换时意识面板跟着变**,与主界面永远一色。
- 用不用随意:官方组件 = 省事 + 风格统一;完全自绘也合法(沙箱与权限不因此有任何差别)。
- 组件库同时是 §9 生成器的原料:agent 生成的意识默认全用官方组件。

## 9. Maker 内置做意识(核心场景)

**目标体验:用户对 agent 说"帮我做一个显示股价的意识",一分钟后桌面上出现能注入的 `.cindy`。**

- 主机内置"做意识"的 agent 技能:官方模板(manifest 骨架 + 组件库样板间)+ 打包工具(目录 → `.cindy`,雏形:`apps/desktop/scripts/pack-cindy.mjs`),agent 负责把用户需求填进模板。
- **意识源码不入主机代码库**(2026-07-09 Lizi 定案):意识是与 desktop 完全解耦的第三方内容,源码住用户自己的目录(约定俗成:`~/Desktop/cindy-ghosts/<id>/`),`.cindy` 生成在同一目录——官方意识(如画图)同样按此形态开发,与用户做意识走同一条路。
- **开发模式注入**:支持把"开发中的意识目录"以链接方式注入(不打包),改代码即热重载面板——这是 agent 自我迭代意识的反馈回路,也是高级用户的手工通道。
- 用户全程不需要读开发文档;复杂规则(manifest 格式、卡槽接口、组件用法)是 agent 的知识,不是用户的负担。
