# 配置设计原则

> 状态：authoritative
> owner：Lizi
> 适用范围：XDMaker 内所有用户可配置项，包括 Settings UI、配置文件、本地数据库偏好、运行时 profile、agent / MCP / provider 相关开关。

## 核心立场

XDMaker 是一个允许高度可定制的开源 AI Agent 产品。用户可以改代码，也应该能够按自己的工作流调整大量配置；产品不应因为“我们不想暴露”而人为封死合理的可配置空间。

但“可配置”不等于“鼓励所有用户随意配置”。默认配置承载创作者对产品节奏、复杂度、审美和工作流的判断，是产品体验的一部分。对大多数用户来说，遵循默认配置应该是最轻松、最稳定、最有价值的路径。

因此，配置设计要同时满足两件事：

1. 高级用户有足够空间定制。
2. 普通用户不被过量选项打扰，默认配置会持续随版本演进。

## 可见性分层

新增或调整配置时，先判定它属于哪一层，而不是默认放进 Settings。

| 层级 | 放置位置 | 适用对象 | 判断标准 |
|---|---|---|---|
| 常规设置 | Settings 默认可见区域 | 大多数用户 | 用户经常需要理解和调整；不展示会影响主路径使用；选项语义清晰，不需要解释内部实现 |
| 高级设置 | Settings 的高级区域 / 折叠菜单 | 少数高级用户 | 有明确用户价值，但误改成本较高、概念较专业、使用频率低，或会改变产品默认工作流 |
| 隐藏配置 | 配置文件 / 本地配置存储 / agent 可编辑配置 | power user / 开发者 | 需要支持定制，但不值得占用 UI 注意力；适合通过自然语言让 agent 修改，或由用户直接编辑配置 |
| 内部常量 | 代码常量，不提供用户配置 | 产品不变量 | 改动会破坏产品语义、安全边界、数据契约或核心体验；不应承诺用户可调 |

不要因为某个值“技术上可以配置”就把它放进 UI。Settings 外层只放需要被大多数用户看到、理解、修改的内容；其余能力应收进高级设置或隐藏配置。

## 默认配置与用户配置

每个配置项都必须区分“系统默认值”和“用户自定义值”。不能只存最终值，否则版本升级时无法判断这个值是用户有意修改，还是旧版本默认值的遗留结果。

设计配置存储时必须满足：

1. 能判断某个配置项是否被用户显式自定义过。
2. 未被用户自定义的配置项，在版本升级后自动采用新的系统默认值。
3. 已被用户自定义的配置项，在版本升级后继续保留用户选择，不被新默认值覆盖。
4. 能把单个配置项或整组配置恢复成当前版本默认值。

推荐把配置表达为“默认配置 + 用户 override”的合并模型。运行时读取有效值时合并两者；持久化时只记录用户 override 以及必要的自定义标记。不要把完整默认配置复制进用户配置后再长期保存，因为这样会让旧默认值看起来像用户选择。

## 默认值演进

默认配置不是一次性初始化脚本，而是产品随版本持续演进的一部分。改默认值时，要明确它对三类用户的影响：

1. 新用户：直接获得新默认值。
2. 未自定义该项的老用户：升级后获得新默认值。
3. 已自定义该项的老用户：保留自己的值，除非存在安全、兼容性或数据迁移原因，且需要明确迁移策略。

如果一个配置项的默认值变更需要迁移，迁移逻辑应基于“是否自定义”的状态判断，而不是基于旧值猜测用户意图。只有在历史数据缺少自定义状态时，才允许写一次性兼容迁移，并在代码或 PR 里说明判断依据和风险。

## Settings UI 原则

Settings 的目标不是展示所有能力，而是帮助用户完成常见决策。

新增 Settings 项目前必须先回答：

1. 这个选项是否需要大多数用户看到？
2. 用户是否能在不理解内部实现的情况下正确选择？
3. 放在外层是否会稀释更重要的设置？
4. 是否更适合放进高级设置、配置文件，或由 agent 通过自然语言修改？

Settings 中必须提供恢复默认的入口。对于配置组，应提供“恢复本组默认”；对于整体设置页，应提供“恢复所有默认设置”。恢复默认的语义是清除对应用户 override，让配置重新跟随当前版本系统默认值，而不是写入一份静态默认值快照。

## Agent 与自然语言配置

XDMaker 应支持用户通过自然语言让 agent 修改本地配置。为此，隐藏配置也必须有清晰 schema、字段说明、取值约束和安全边界，不能依赖零散代码分支或隐式约定。

Agent 修改配置时应遵守同一套默认/override 模型：用户明确要求修改时写入 override；用户要求恢复默认时删除 override；不应把当前默认值固化写回用户配置。

## 实现要求

新增或修改配置项时，PR 至少说明：

1. 配置属于常规设置、高级设置、隐藏配置还是内部常量。
2. 默认值是什么，为什么这是创作者推荐的默认体验。
3. 用户 override 如何记录，如何判断是否自定义。
4. 默认值未来变化时，未自定义用户如何跟随更新。
5. 恢复默认如何实现，清除的是哪个 override。

如果配置进入 Settings UI，还必须遵守 UI / i18n / 主题 token 等现有规则，并避免把专业或低频选项堆在默认可见区域。
