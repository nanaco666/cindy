A session can run inside its own **git worktree** — a separate working copy of the same repository on its own branch — so the agent's edits don't mix with your main checkout.

**Opting in:**

- In the new-chat view, click the working-directory chip → the **gear** icon to open the Advanced popover → tick the **worktree** checkbox.
- The worktree is created **on first message send**, not on session create. An overlay shows the status (creating / ready / failed).

**Where it goes:**

- Folder: `<repo>/.xdt-worktrees/<auto-generated-name>/` — kept inside the same repo so git tooling can find it.
- Branch: `xdt/<auto-generated-name>` — auto-created off the current HEAD.

**Lifecycle:**

- Created on first agent turn that needs files.
- Survives across app restarts as long as the session is around.
- When you **archive** or **close** the session, the worktree folder is removed; the **branch is preserved** (no force-delete), so you can keep the work or merge / cherry-pick from it later.
- Uncommitted changes inside the worktree are **auto-stashed** before the folder is removed, so nothing is silently lost.

**When the option is disabled:**

- Git is not installed on your machine.
- The chosen working directory isn't a git repository.
- The chosen directory is already inside an existing worktree (no nesting).

**Error cases (shown on the overlay):**

- `permission-denied` (can't write into the repo dir), `git-crypt-locked` (repo uses git-crypt and isn't unlocked), `dubious-ownership` (git's safe.directory check tripped), `lfs-error`, `not-a-git-repo`, `git-not-installed`.

**Notes:**

- The agent's **Read / Write / Bash** tools automatically operate inside the worktree path — you don't need to switch directories manually.
- Because the branch survives the worktree, "did the agent's changes go anywhere?" is always answerable with `git branch --list 'xdt/*'`.
- Worktrees are a per-session opt-in — they're not on by default and they don't change non-worktree sessions in any way.
